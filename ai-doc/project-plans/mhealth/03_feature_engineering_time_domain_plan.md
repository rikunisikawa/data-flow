# MHEALTH Feature Engineering Plan: 時間領域特徴量の作成

## 1. 目的

dbt を活用し、人間活動認識タスクで一般的に有効とされる時間領域の特徴量を効率的に計算する。SQLのウィンドウ関数を駆使して、スライディングウィンドウ法に基づいた特徴量テーブルを構築する。

## 2. 背景

センサーデータのような時系列データから直接パターンを学習するのは困難な場合がある。そのため、データの統計的な特性を捉える「特徴量」を設計することが重要となる。時間領域の特徴量は、信号の形状や強度を要約する基本的な指標であり、多くの機械学習モデルで入力として利用される。

## 3. タスク詳細

### 3.1. ウィンドウの定義

- **作業内容**:
    1.  特徴量を計算するための時間ウィンドウのサイズと、ウィンドウをスライドさせるステップサイズ（オーバーラップ）を決定する。多くのHAR研究では、**2.56秒のウィンドウ**と**50%のオーバーラップ**が一般的に用いられるため、これをデフォルト値とする。
    2.  `dbt_project.yml` の `vars` を使用して、これらの値を設定し、モデル内で参照できるようにする。これにより、後からウィンドウサイズを容易に変更できるようになる。
        ```yaml
        # dbt_project.yml
        vars:
          mhealth_window_size_seconds: 2.56
          mhealth_window_overlap_percentage: 0.5
        ```

### 3.2. ウィンドウ生成モデルの作成

- **作業内容**:
    1.  `int_mhealth_cleaned` モデルを基に、各レコードがどのウィンドウに属するかを識別するIDを付与するdbtモデルを作成する。
    2.  タイムスタンプと `vars` で定義したウィンドウサイズ・オーバーラップ率を用いて、ウィンドウIDを計算するロジックを実装する。

- **成果物**:
    - dbt モデル: `models/mhealth/intermediate/int_mhealth_windowed.sql`

### 3.3. 時間領域特徴量の計算

- **作業内容**:
    1.  `int_mhealth_windowed` モデルを `GROUP BY window_id` で集約し、各ウィンドウ内のセンサーデータ（加速度、ジャイロなど）に対して以下の特徴量を計算する。
        - **基本統計量**: `avg`, `stddev`, `min`, `max`, `median`
        - **強度に関する特徴量**: `avg(abs(signal))` (平均絶対値), `sum(power(signal, 2))` (エネルギー)
        - **その他の特徴量**: `max(signal) - min(signal)` (レンジ)
    2.  これらの計算を、すべてのセンサー軸（例: `acc_x`, `acc_y`, `acc_z`）に対して行う。

- **成果物**:
    - dbt モデル: `models/mhealth/features/fct_mhealth_time_domain_features.sql`

## 4. 完了条件

- `dbt run` が `fct_mhealth_time_domain_features` モデルまで正常に完了する。
- 生成された特徴量テーブルの各行が、一意のウィンドウIDに対応している。
- 計算された特徴量の値が、手計算によるサンプルチェックの結果と一致し、妥当であることが確認できる。
- モデルのロジックと各特徴量の定義が、dbtの `description` として記述されている。
