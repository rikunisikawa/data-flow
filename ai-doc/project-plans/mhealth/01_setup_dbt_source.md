# タスク1.1: dbtソースの定義とデータ品質の確認

## 目的

MHEALTHデータセットの生データをdbtのソースとして正式に定義し、基本的なデータクレンジングと品質評価を行うための基盤を構築する。
これにより、下流のdbtモデルが信頼性の高いデータソースを利用できるようにする。

## 背景

現在、MHEALTHデータセットはS3の特定のパスに格納され、Glue Catalogを介してAthenaでクエリ可能な状態にある。
しかし、dbtプロジェクト内ではまだ正式な「ソース」として定義されていない。
ソースとして定義することで、dbtの機能を活用したデータ品質テストや鮮度管理が可能になる。

## 作業内容

1.  **`src_mhealth.yml` の作成または更新**
    -   `models/` ディレクトリに `src_mhealth.yml` という名前のファイルを作成する。
    -   このファイル内に、MHEALTHデータセットの生データテーブル（例: `raw_activities`）をソースとして定義する。
    -   `database`, `schema`, `name` を適切に設定する。

2.  **データ品質テストの追加**
    -   定義したソースに対して、基本的なデータ品質テストを追加する。
    -   最低限、以下のテストを実装する。
        -   `not_null`: 主要なカラム（被験者ID、タイムスタンプ、センサー値など）がNULLでないことを確認する。
        -   `unique`: 各レコードが一意であることを確認するための主キー（または代理キー）を定義し、テストする。
        -   `accepted_values`: 活動ラベルなど、特定の値しか取らないカラムに対して、許容される値のリストを定義しテストする。

3.  **データ鮮度（Freshness）の設定**
    -   ソーステーブルが定期的に更新されることを想定し、dbtの鮮度チェック機能を追加する。
    -   `loaded_at_field` にデータの読み込み日時を示すカラムを指定する。
    -   `warn_after` と `error_after` を設定し、データ更新の遅延を検知できるようにする。

## 期待される成果物

-   `models/src_mhealth.yml` ファイルが作成・更新され、MHEALTHデータセットのソース定義とテストが記述されていること。
-   `dbt source snapshot-freshness` を実行し、エラーが発生しないこと。
-   `dbt test --select source:*` を実行し、すべてのテストがパスすること。
