# 開発フロー自動化ガイド (`auto-pr.yml`)

## 1. 概要

このドキュメントは、本リポジトリに導入されている開発フロー自動化ワークフロー (`.github/workflows/auto-pr.yml`) の利用方法を解説します。

このワークフローは、[Spec Kit](https://github.com/gemini-spec/spec-kit) の思想に基づき、**Issueの起票から仕様・計画の策定、AIによるコード実装、Pull Requestの作成まで**の一連のプロセスを半自動化し、開発効率を劇的に向上させることを目的としています。

### ワークフローの全体像

```mermaid
graph TD
    A[Start: Issue起票] --> B{Planフェーズ};
    B --> C[1. AIが仕様/計画を生成];
    C --> D[2. ブランチ作成];
    D --> E[3. PR作成 (レビュー依頼)];
    E --> F{開発者がレビュー};
    F -- 承認 --> G{Implementフェーズ};
    F -- 修正依頼 --> B;
    G --> H[1. /execute コメントで開始];
    H --> I[2. AIがコードを実装];
    I --> J[3. コミット & プッシュ];
    J --> K[End: PR更新 (レビュー依頼)];
```

## 2. ワークフローのフェーズ

ワークフローは、大きく分けて「Plan（計画）」と「Implement（実装）」の2つのフェーズで構成されます。

### 2.1. Planフェーズ: 仕様と計画の自動生成

開発の初期段階で、Issueから仕様と計画を策定し、開発準備を整えるフェーズです。

- **トリガー:**
  - 開発者が新しいIssueをオープン、またはリオープンしたとき。
- **処理内容:**
  1.  **AIによる仕様・計画生成:** Issueのタイトルと本文を基に、AI (Gemini) がSpec Kitの規約に従った仕様 (`spec.md`)、計画 (`plan.md`)、タスク (`tasks.md`) を `specs/` ディレクトリ配下に自動生成します。
  2.  **ブランチ作成:** 仕様書に記述された、あるいは自動生成されたフィーチャーブランチ（例: `feature/issue-123`）を作成します。
  3.  **Pull Request作成:** 生成された仕様・計画ファイルを含むブランチから、`main` ブランチに対するPull Requestを自動で作成します。
- **成果物:**
  - `specs/` ディレクトリ配下に生成された仕様・計画・タスクファイル。
  - `plan` ラベルが付与された、計画レビュー用のPull Request。

### 2.2. Implementフェーズ: AIによるコード実装

策定された計画に基づき、AIが実際のコード変更を行うフェーズです。

- **トリガー:**
  - 開発者が、Planフェーズで作成されたPR、または関連するIssueのコメント欄で `/execute` と入力したとき。
- **処理内容:**
  1.  **コンテキスト収集:** Issueの内容、関連する計画ファイル、そして `/execute` コメントの全文をコンテキストとして収集します。
  2.  **AIによるコード実装:** 収集したコンテキストを基に、AI (Gemini) がコードの新規作成、修正、削除などの変更をリポジトリに対して直接行います。
  3.  **コミット & プッシュ:** AIによる変更内容を、対象のフィーチャーブランチに自動でコミットし、リモートリポジトリにプッシュします。
  4.  **PRの更新:** 既存のPRのタイトルと本文を、AIが生成したサマリーで更新します。
- **成果物:**
  - AIによって実装・変更されたコード。
  - 変更内容が反映された既存のPull Request。

## 3. 開発者の利用手順

開発者は以下の手順で、本ワークフローを活用して開発を進めます。

1.  **Issueの起票:**
    - 実装したい機能や修正したいバグについて、具体的な内容を記述したIssueを作成します。
    - これにより、Planフェーズが自動的に開始されます。
2.  **計画のレビュー:**
    - ワークフローによって自動生成されたPull Requestを開きます。
    - AIが生成した仕様 (`spec.md`) と計画 (`plan.md`) を確認します。
    - **計画を承認する場合**は、次のステップに進みます。
    - **計画を修正したい場合**は、PR上で修正案や追加の要件をコメントし、AIに計画を修正させます。
3.  **実装の指示:**
    - 計画内容に問題がなければ、PRまたはIssueのコメント欄で `/execute` とコメントし、AIに実装を指示します。
    - これにより、Implementフェーズが開始されます。
4.  **コードのレビュー:**
    - AIがフィーチャーブランチにプッシュしたコード変更を、PR上でレビューします。
    - 必要であれば、追加の修正をAIに指示するか、手動でコードを修正します。
5.  **マージ:**
    - コードが完成し、テストが通ることを確認したら、Pull Requestをマージします。
