# Gemini CLIを使いこなすためのTips

Gemini CLIは、ターミナルからGoogleのAIモデル「Gemini」を対話的に利用できる強力なオープンソースツールです。コード生成やリファクタリング、プロジェクト全体の分析など、開発者の生産性を向上させるための様々な機能を提供します。

## 1. 基本的な使い方

### 対話モードと非対話モード

- **対話モード**: `gemini` コマンドで起動し、チャット形式でAIと対話します。設計の相談や段階的なコード改善に適しています。
- **非対話モード**: `-p` または `--prompt` フラグを使い、単一のプロンプトを渡して結果だけを受け取ります。スクリプトやCI/CDパイプラインでの自動化に最適です。
  ```bash
  # カレントディレクトリのコード品質を解析させる
  gemini -p "このディレクトリのコード品質を解析して"
  ```

### コンテキストのカスタマイズ (`GEMINI.md`)

プロジェクトのルートやホームディレクトリに `GEMINI.md` ファイルを配置することで、AIの振る舞いをカスタマイズできます。コーディング規約、プロジェクトの背景、制約事項などを記述しておけば、AIがそれを前提知識として対話に応じます。

- **スコープ**:
    - `~/.gemini/GEMINI.md`: 全プロジェクト共通のルール
    - `プロジェクトルート/GEMINI.md`: プロジェクト固有のルール
    - `サブディレクトリ/GEMINI.md`: モジュール固有のルール
- **確認方法**: 対話中に `/memory show` コマンドで、読み込まれているコンテキストを確認できます。

## 2. 便利なコマンドとフラグ

### 起動オプション（フラグ）

| フラグ | 説明 |
|:---|:---|
| `-m, --model` | 使用するモデルを指定します (例: `gemini-2.5-flash`)。 |
| `-p, --prompt` | 非対話モードで実行します。 |
| `-y, --yolo` | 全てのアクションを自動承認します。CI/CDでの利用に便利ですが、リスクも伴います。 |
| `-s, --sandbox` | Dockerコンテナ内でツールを実行し、ホスト環境を保護します。 |
| `-d, --debug` | デバッグログを出力します。 |
| `--checkpointing` | ファイル変更前にスナップショットを保存し、`/restore` で復元できるようにします。 |

### 対話内コマンド（スラッシュコマンド）

| コマンド | 説明 |
|:---|:---|
| `/tools` | 利用可能なツールの一覧を表示します。 |
| `/memory show` | 現在読み込まれているコンテキスト（`GEMINI.md`の内容など）を表示します。 |
| `/memory refresh` | コンテキストファイルを再読み込みします。 |
| `/restore` | 保存されたチェックポイントからプロジェクトの状態を復元します。 |
| `/compress` | 長くなった対話履歴を要約し、トークンを節約します。 |
| `/copy` | 直前のAIの回答をクリップボードにコピーします。 |
| `/chat save <タグ>` | 現在の対話を保存します。 |
| `/chat resume <タグ>` | 保存した対話を再開します。 |
| `/help` | 全てのコマンド一覧を表示します。 |

## 3. CI/CDでの自動化

### GitHub Actionsとの連携

公式の [Gemini CLI Action](https://github.com/google-gemini/gemini-cli-action) を利用することで、Pull Requestへの自動レビューやIssueのトリアージなどを実現できます。

- **例**: PRコメントで `@gemini-cli /review` と入力すると、AIがPR内容をレビューしコメントします。

### パイプラインへの統合

JenkinsやGitLab CIなどの環境でも、以下の設定を行うことでGemini CLIを組み込めます。

1.  **APIキー認証**: CI環境の環境変数 `GEMINI_API_KEY` にAPIキーを設定します。
2.  **YOLOモード**: `-y` フラグで自動実行を許可します。
3.  **セキュリティ対策**:
    - **ツール制限**: `settings.json` で不要なツール（例: `rm`）を無効化します。
    - **サンドボックス**: `--sandbox` オプションやDockerイメージを活用し、実行環境を隔離します。

## 4. セキュリティのベストプラクティス

- **APIキー管理**: APIキーは環境変数や `~/.gemini/.env` ファイルで管理し、ソースコードに含めないでください。
- **権限制御**: `settings.json` の `includeTools` / `excludeTools` で、AIが使用できるツールを必要最小限に絞ります。
- **YOLOモードの注意**: 自動でファイル変更やコマンド実行が行われるため、サンドボックス環境での実行や、変更内容のレビュープロセスを組み合わせることが推奨されます。

## 5. コミュニティの活用

- **カスタムコマンド**: `.toml` ファイルで独自のコマンドを定義し、定型作業を自動化できます。コミュニティで便利なコマンドが共有されています。
- **「計画→実装」アプローチ**: いきなり実装を指示するのではなく、`/plan` のようなカスタムコマンドでまず計画を立てさせ、レビュー後に実装を指示することで、手戻りを減らし品質を向上させることができます。
