# 仕様: SpecKitを導入したワークフローのドキュメント作成

## 1. 目的

`auto-pr.yml` ワークフローの導入により、Issue駆動での開発フローが半自動化された。
本仕様では、この新しい開発フローを開発者が理解し、円滑に利用できるよう、公式なドキュメントを作成することを目的とする。

## 2. 背景

これまで、開発フローはドキュメントに記載されていたが、`auto-pr.yml` の導入により実際のフローとドキュメントの間に乖離が生じている。
SpecKitの導入テストも兼ねて、現状のワークフローに基づいた正確なドキュメントを整備する必要がある。

## 3. 機能要件

作成するドキュメントには、以下の内容を含むこと。

- **ワークフローの概要**: Issue起票からPull Requestが作成されるまでの一連の流れ。
- **トリガー条件**: ワークフローが開始される具体的なイベント（Issue作成、コメントなど）。
- **開発者の操作**:
    - 計画のレビュー方法。
    - 実装を指示する方法（例: `/execute` コメント）。
- **成果物**: ワークフローによって自動生成されるブランチ、Pull Request、Spec Kit関連ファイル。
- **注意事項**: ワークフローを利用する上での注意点や制約事項。

## 4. 成果物

- 開発フロードキュメント (Markdown形式)
- 格納先: `.github/docs/development-flow.md` （新規作成）
