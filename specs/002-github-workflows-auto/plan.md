# 実装計画: auto-pr.ymlをspec-kitを使用するようにリファクタリング

**ブランチ**: `002-github-workflows-auto` | **日付**: 2025-09-07 | **仕様書**: [./spec.md](./spec.md)
**入力**: `/specs/002-github-workflows-auto/spec.md`からの機能仕様書

## 概要
この計画は、既存の`.github/workflows/auto-pr.yml` GitHub Actionsワークフローをリファクタリングする手順の概要を示します。目標は、`spec-driven-development.yml`ワークフローと同様の`spec-kit`駆動開発プロセスを採用することです。これにより、Issue作成からプルリクエスト生成までのプロセスが合理化され、よりモジュール化され、保守しやすくなります。

## 技術的背景
**言語/バージョン**: YAML (GitHub Actions用)
**主な依存関係**: `spec-kit`, `uv`, `google-gemini/gemini-cli-action`
**ストレージ**: N/A
**テスト**: テストIssueによるワークフローの手動トリガー
**ターゲットプラットフォーム**: GitHub Actions
**プロジェクトタイプ**: CI/CDワークフロー
**制約**: 変更されたワークフローは`.github/workflows`ディレクトリ内のファイルを編集してはならない。

## 構成チェック
この変更は主にCI/CDワークフローに影響を与え、自動化とモジュール性の既存の原則に準拠しています。違反は予想されません。

## プロジェクト構造
- 変更される主なファイルは`.github/workflows/auto-pr.yml`です。
- ソースコード構造の変更は計画されていません。

## フェーズ0: 概要と調査
1.  **`auto-pr.yml`と`spec-driven-development.yml`の分析**: `spec-kit`駆動アプローチを採用するために必要なすべての変更を特定します。(完了)
2.  **`uv`と`spec-kit`のインストールの確認**: GitHub Actions環境内で`uv`と`spec-kit`が正しくインストールおよび使用できることを確認します。

## フェーズ1: 設計と契約
このフェーズは、データモデルやAPIを持つ新機能を開発するのではなく、ワークフローを変更するため、直接適用できません。「契約」は、仕様書で定義されている新しいワークフローの期待される動作と見なすことができます。

## フェーズ2: タスク計画アプローチ
*このセクションでは、/tasksコマンドが何をするかを説明します - /planの実行中には実行しないでください*

**タスク生成戦略**:
1.  **`setup_spec_kit`ジョブの追加**: `auto-pr.yml`に、`uv`のインストールと、存在しない場合に`spec-kit`テンプレートの初期化を担当する新しいジョブを作成します。
2.  **`plan`ジョブのリファクタリング**:
    - `setup_spec_kit`ジョブへの依存関係を追加します。
    - 現在のGeminiプロンプトを、`spec-kit`の`/specify`および`/plan`コマンドを利用する新しいプロンプトに置き換えます。
    - `spec-kit`スクリプトの出力からブランチ名と仕様ディレクトリを抽出するロジックを更新します。
3.  **`implement`ジョブのリファクタリング**:
    - `setup_spec_kit`ジョブへの依存関係を追加します。
    - 機能ブランチに対応する`specs/`ディレクトリ内の`plan.md`ファイルを見つけるロジックを変更します。
    - `implement`コマンドを使用するようにGeminiプロンプトを更新し、正しい`plan.md`ファイルへのパスを提供します。
4.  **テスト戦略**:
    - 変更されたワークフローをトリガーするために、特定のラベルを持つテストIssueを作成します。
    - ワークフローが正常に実行され、新しいブランチ、仕様ファイル、計画ファイル、およびプルリクエストが作成されることを確認します。
    - 実装フェーズをトリガーするために、テストIssueまたはPRに`/execute`コメントを投稿します。
    - 実装が正しく実行され、変更が機能ブランチにプッシュされることを確認します。
