- [ ] T001 [P] 既存の`.github/workflows/auto-pr.yml`ファイルのバックアップを`.github/workflows/auto-pr.yml.bak`に作成します。

## フェーズ 3.2: リファクタリング
- [ ] T002 新しい`setup_spec_kit`ジョブを`.github/workflows/auto-pr.yml`に追加します。このジョブは`uv`のインストールと`spec-kit`テンプレートの初期化を担当します。
- [ ] T003 `.github/workflows/auto-pr.yml`の`plan`ジョブを、`setup_spec_kit`への依存関係を追加するように変更します。
- [ ] T004 `plan`ジョブの既存のGeminiプロンプトを、`spec-kit`の`/specify`および`/plan`コマンドを使用する新しいプロンプトに置き換えます。
- [ ] T005 `plan`ジョブのロジックを更新して、`spec-kit`スクリプトの出力からブランチ名と仕様ディレクトリを抽出します。
- [ ] T006 `.github/workflows/auto-pr.yml`の`implement`ジョブを、`setup_spec_kit`への依存関係を追加するように変更します。
- [ ] T007 `implement`ジョブのロジックを更新して、`specs/`ディレクトリ内の`plan.md`ファイルを見つけます。
- [ ] T008 `implement`ジョブのGeminiプロンプトを更新して、正しい`plan.md`ファイルへのパスを指定して`implement`コマンドを使用します。

## フェーズ 3.3: テスト
- [ ] T009 変更されたワークフローをトリガーするために、特定のラベルを持つテストIssueを作成します。
- [ ] T010 ワークフローが正常に実行され、新しいブランチ、仕様ファイル、計画ファイル、およびプルリクエストが作成されることを確認します。
- [ ] T011 実装フェーズをトリガーするために、テストIssueまたはPRに`/execute`コメントを投稿します。
- [ ] T012 実装が正しく実行され、変更が機能ブランチにプッシュされることを確認します。

## フェーズ 3.4: クリーンアップ
- [ ] T013 [P] バックアップファイル`.github/workflows/auto-pr.yml.bak`を削除します。

## 依存関係
