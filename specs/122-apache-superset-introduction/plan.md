# [高レベル計画] Apache Superset 導入 (issue #122)

## 概要
本計画は、既存のデータ基盤に Apache Superset を可視化レイヤーとして導入するための高レベルな手順を定義します。dbt を Single Source of Truth とする原則を維持し、Superset は参照専用のツールとして位置づけます。

## 計画フェーズ

1.  **【Phase 1】 環境構築と初期設定**
    - Docker と Docker Compose を利用して、Apache Superset の実行環境を構築します。
    - 日本のタイムゾーン（Asia/Tokyo）やロケール（ja）など、基本的な初期設定を行います。
    - この段階で、Superset がローカルで起動し、管理画面にアクセスできることを目指します。

2.  **【Phase 2】 データソースへの接続**
    - 既存のクエリエンジンである Amazon Athena への接続を設定します。
    - 接続には、読み取り専用の権限を持つ IAM ユーザーを使用し、セキュリティを確保します。
    - Glue Data Catalog と Athena のクエリ結果用 S3 バケットへの参照権限が必要です。

3.  **【Phase 3】 データセットの定義**
    - dbt によって生成された Gold 層のテーブルを、Superset の「Dataset」として登録します。
    - dbt のモデル名と Superset の Dataset 名を一致させ、管理の整合性を保ちます。
    - Silver 層や Bronze 層のテーブルは登録対象外とします。

4.  **【Phase 4】 可視化とダッシュボードの作成**
    - 登録した Dataset を基に、主要な KPI やビジネス指標を可視化するチャートを作成します。
    - 作成したチャートをまとめ、目的別のダッシュボードを構築します。
    - Superset 上での複雑な SQL JOIN やビジネスロジックの追加は行わず、dbt の定義をそのまま利用します。

5.  **【Phase 5】 ドキュメントと運用ルールの整備**
    - 構築した Superset 環境の構成、設定手順、運用ルールをドキュメントにまとめます。
    - dbt と Superset の責務分担を明確にし、今後の運用者が迷わないようにガイドラインを整備します。
