# Plan for Feature: 新しいauto-pr.ymlワークフローの動作確認

## フェーズ1: `plan` ジョブの動作検証

1.  **テストIssueの作成 (手動)**
    *   **担当**: 開発者
    *   **内容**:
        *   リポジトリに新しいIssueを作成する。
        *   **タイトル**: `[Test-89] auto-pr.yml plan job verification`
        *   **本文**: `This is a test issue to verify the 'plan' job of the auto-pr.yml workflow.`
    *   **確認**: Issue作成後、Actionsタブで `Plan and Implement on Issue` ワークフローが起動することを確認する。

2.  **自動生成されたPRの確認 (手動)**
    *   **担当**: 開発者
    *   **内容**:
        *   ワークフロー完了後、新しいPull Requestが作成されていることを確認する。
        *   PRのタイトルが `Spec: feature/issue-XXX ...` となっていることを確認する。
        *   PRのブランチ名が `feature/issue-XXX` であることを確認する。
        *   PRの本文に、仕様ディレクトリへのリンクが含まれていることを確認する。
        *   PRの変更ファイル（Files changedタブ）に、`specs/XXX-.../` 配下のファイル群が含まれていることを確認する。
    *   **完了条件**: 上記すべての確認項目が満たされていること。

## フェーズ2: `implement` ジョブの動作検証

1.  **`/execute` コメントの投稿 (手動)**
    *   **担当**: 開発者
    *   **内容**: フェーズ1で作成されたIssueまたはPRに、`/execute` という内容でコメントを投稿する。
    *   **確認**: コメント投稿後、Actionsタブで `Plan and Implement on Issue` ワークフローが再度起動することを確認する。

2.  **PRの更新内容の確認 (手動)**
    *   **担当**: 開発者
    *   **内容**:
        *   ワークフロー完了後、フェーズ1で作成されたPRが更新されていることを確認する。
        *   PRのコミット履歴に、`feat: implement according to spec-kit plan` のようなメッセージを持つ新しいコミットが追加されていることを確認する。
        *   PRのタイトルが `feat: implement feature/issue-XXX` のように変更されていることを確認する。
        *   PRの本文が、実装の概要を示す内容に更新されていることを確認する。
    *   **完了条件**: 上記すべての確認項目が満たされていること。

## フェーズ3: 後片付け

1.  **テストPRのマージまたはクローズ (手動)**
    *   **担当**: 開発者
    *   **内容**: 検証が完了したら、テスト用に作成されたPRをマージまたはクローズする。関連するフィーチャーブランチも削除する。

2.  **検証結果の記録 (手動)**
    *   **担当**: 開発者
    *   **内容**: 本Issue(#89)のスペックディレクトリ（`specs/003-89-verify-auto/`）に、検証結果をまとめた `research.md` を作成し、コミットする。
