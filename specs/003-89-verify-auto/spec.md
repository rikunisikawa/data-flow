# Specification for Feature: 新しいauto-pr.ymlワークフローの動作確認

## 1. 機能概要
`auto-pr.yml` GitHub Actionsワークフローが、Issueのライフサイクル（起票、コメント）に応じて、Spec Kitプロセス（計画、実装、PR作成・更新）を正しく自動実行できることを確認する。

## 2. 背景
開発プロセスの効率化のため、Issue起票からPR作成、実装までを自動化する`auto-pr.yml`が導入された。このワークフローが意図通りに動作するかを、実際のイベントを発生させて検証する必要がある。

## 3. ゴール
- `plan`ジョブがIssue起票時にトリガーされ、仕様と計画を含むPRを自動作成すること。
- `implement`ジョブが`/execute`コメントによってトリガーされ、既存のPRをコード変更で更新すること。

## 4. 検証シナリオ
1.  **`plan`ジョブの検証**:
    -   **手順**: 新規にテスト用Issueを作成する。
    -   **期待される結果**:
        -   `auto-pr.yml`ワークフローが起動する。
        -   `feature/issue-XXX`形式のブランチが作成される。
        -   `specs/XXX-description`ディレクトリと仕様ファイル群が作成・コミットされる。
        -   仕様と計画のレビューを促すPull Requestが自動で作成される。

2.  **`implement`ジョブの検証**:
    -   **手順**: 上記で作成されたIssueまたはPRに、`/execute`とコメントする。
    -   **期待される結果**:
        -   `auto-pr.yml`ワークフローが再度起動する。
        -   `implement`ジョブが実行される。
        -   計画に基づいたコード変更が対象ブランチにコミット＆プッシュされる。
        -   既存のPull Requestのタイトルと本文が、実装内容を反映したものに更新される。

## 5. 非機能要件
- `auto-pr.yml`ファイル自体は変更しない。
