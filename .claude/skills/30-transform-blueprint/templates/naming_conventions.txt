==============================================================
Naming Conventions — 命名規約
==============================================================
プロジェクト: [PROJECT_NAME]
適用範囲:    テーブル / カラム / ファイル / ディレクトリ / ジョブ

--------------------------------------------------------------
テーブル命名規約
--------------------------------------------------------------
レイヤプレフィックス:
  src_  : ソース（生データ）
  stg_  : ステージング（クレンジング済み）
  int_  : 中間テーブル（結合/集計途中）
  fct_  : ファクトテーブル（集計済み事実）
  dim_  : ディメンションテーブル（マスタ）
  rpt_  : レポート用テーブル

形式:   [prefix]_[domain]_[entity]
例:     stg_mhealth_sensor_log
        fct_activity_daily_agg
        dim_user_master

--------------------------------------------------------------
カラム命名規約
--------------------------------------------------------------
ケース:       snake_case（すべて小文字）
禁止:         略語の独自定義（例: cnt → count, dt → date を使う）
日付/時刻:    _at（timestamp型）, _date（date型）, _year, _month, _day
フラグ:       is_, has_, can_ プレフィックス（例: is_active, has_pii）
ID:           _id サフィックス（例: user_id, session_id）
金額:         _amount サフィックス（例: revenue_amount）
件数:         _count サフィックス（例: session_count）

--------------------------------------------------------------
ファイル命名規約
--------------------------------------------------------------
形式: YYYYMMDD_[slug]_[layer].[ext]
例:
  20260223_medication-kpi_raw.log
  20260223_medication-kpi_stage.parquet
  20260223_medication-kpi_report.txt

--------------------------------------------------------------
ディレクトリ命名規約
--------------------------------------------------------------
artifacts/YYYYMMDD_[slug]/  ← 成果物の置き場
docs/                       ← 設計・運用ドキュメント
.claude/skills/[NN-name]/   ← Skillの定義

--------------------------------------------------------------
ジョブ/Lambda 命名規約
--------------------------------------------------------------
形式: [domain]-[action]-[layer]
例:
  mhealth-download-raw
  mhealth-convert-stage
  mhealth-transform-processed

--------------------------------------------------------------
Gitブランチ命名規約
--------------------------------------------------------------
形式: [type]/[slug]-[ticket-id]
type: feature / fix / refactor / docs / chore
例:   feature/medication-kpi-123

--------------------------------------------------------------
適用例（本プロジェクト既存との整合）
--------------------------------------------------------------
既存Lambda:
  download_and_upload      → mhealth-download-raw に相当
  convert_log_to_parquet   → mhealth-convert-stage に相当

新規テーブル:
  stg_mhealth_sensor_log   → stage層のセンサログ
  fct_activity_daily       → 日次集計ファクトテーブル
