Monitoring Plan — 監視計画
==============================================================
依頼識別子: [SLUG]

 適用はL3承認後にSRE/エンジニアが実施する。]

--------------------------------------------------------------
1. 監視の対象と目的
--------------------------------------------------------------
対象:
  - データパイプライン全体（Lambda①→②→Glue相当）
  - S3への書き込み成否
  - 出力データの品質（data_quality_plan.txtのルールと連動）

目的:
  - SLO（slos_slis.txt参照）の達成を確認する
  - 障害を早期に検知し、runbook_incident.txtで対応する

--------------------------------------------------------------
2. 監視項目と閾値
--------------------------------------------------------------
## インフラ系
| 項目                  | 正常範囲     | アラート閾値  | 重要度 |
|---------------------|------------|------------|------|
| Lambda実行時間         | < [60]s    | > [180]s   | P2   |
| Lambda エラー率        | < 1%       | > 5%       | P1   |
| Glue Job 実行時間      | < [30]min  | > [60]min  | P2   |
| Glue Job 失敗         | 0件         | >= 1件     | P1   |

## データ品質系
| 項目                  | 正常範囲     | アラート閾値  | 重要度 |
|---------------------|------------|------------|------|
| 鮮度（最新レコードの経過時間）| < [24]h  | > [48]h   | P1   |
| 出力レコード数の変動    | ±[30]%以内  | ±[50]%超   | P2   |
| NULLレート（必須カラム）| 0%         | > 0%       | P0   |
| スキーマ変更検知        | なし        | 変更検知    | P0   |

重要度定義:
  P0 = 即時対応（夜間でも対応）
  P1 = 4時間以内
  P2 = 翌営業日中

--------------------------------------------------------------
3. アラート通知設定（プレースホルダ）
--------------------------------------------------------------
P0アラート通知先: [pagerduty_service / slack_channel]
P1アラート通知先: [slack_channel]
P2アラート通知先: [slack_channel または Jira自動登録]

[secrets（webhook URL等）はこのファイルに記載しない。AWS Secrets Managerで管理]

--------------------------------------------------------------
4. ダッシュボード設計
--------------------------------------------------------------
推奨ダッシュボード（ツールは実装者が選択）:
  - パイプライン成功率（直近7日）
  - 鮮度チャート（最新レコードのタイムスタンプ）
  - エラーレートトレンド
  - データ件数の時系列変動

--------------------------------------------------------------
5. エスカレーションフロー
--------------------------------------------------------------
検知 → オンコール担当（runbook_incident.txtを参照）
  → 30分で未解決 → テックリードに連絡
  → 2時間で未解決 → データオーナーと合同対応
