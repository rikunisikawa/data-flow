# Skill: data-governance-guard

## 目的
データ内のPII（個人識別情報）疑いカラムを分類し、
承認必要性の提示とマスキング方針を策定するスキル。
データへのアクセス・変更は行わない。

## 対象（本プロジェクト）
mHealth データセットの各カラムとパイプライン全体を対象とする。

## 提供する成果物
1. **PIIリスク分類表**: カラム別のリスクレベル（高/中/低/なし）
2. **承認マトリックス**: 利用用途別に必要な承認レベル
3. **マスキング方針**: PIIカラムの処理方針
4. **コンプライアンスチェックリスト**: GDPR/個人情報保護法観点

## 使用方法
```
# Orchestratorからの呼び出し例
[data-governance-guard]: mHealthデータセットのPIIリスクを評価し、
                         マスキング方針を提示してください。
```

## 禁止事項
- 実データへのアクセス
- マスキング処理の実行
- データの削除・変更
- PIIデータを含むログの出力

## PIIリスク分類表（mHealth Dataset）
| カラム名        | PII疑い | リスクレベル | 根拠                          |
|---------------|---------|------------|------------------------------|
| timestamp     | なし    | 低         | Unixタイムスタンプのみ         |
| acc_chest_x/y/z | なし  | 低         | 匿名センサ値                  |
| ecg_lead1/2   | 疑いあり | 中        | 心電図は生体情報、個人識別可能性あり |
| acc_ankle_x/y/z | なし  | 低         | 匿名センサ値                  |
| acc_arm_x/y/z | なし    | 低         | 匿名センサ値                  |
| activity_label| なし    | 低         | 活動種別の整数ラベル           |

## 承認マトリックス
| 利用用途             | 必要承認レベル | 備考                          |
|--------------------|-------------|------------------------------|
| 匿名分析・集計       | L1 (自動承認) | 個人識別不可の集計値のみ       |
| EDA（サンプル）      | L1 (自動承認) | 匿名化済みサンプルに限る       |
| モデル学習（ECG含む）| L2 (管理者承認)| 生体情報を含む場合は要承認    |
| 外部連携・共有       | L3 (法務承認) | 必ずマスキング後に実施         |
| 生データ参照         | L2 (管理者承認)| アクセスログを必ず記録         |

## マスキング方針
```
ECGデータ（ecg_lead1, ecg_lead2）:
  - 外部共有時: k-匿名化または差分プライバシー適用
  - 分析用途: 集計値のみ使用し、個人レベルデータは非公開
  - 保持期間: 収集から2年以内に削除または匿名化完了

タイムスタンプ:
  - 個人特定に使える粒度（秒単位以下）は集計時にバケット化する
  - 例: 1時間単位に丸める

実装方針（設計のみ、実行禁止）:
  - Glue Job内でECGカラムをHash化またはNull化するオプションを設計
  - マスキング済みテーブルと生データテーブルをIAMで分離
```

## コンプライアンスチェックリスト
- [ ] 被験者からのデータ利用同意を確認したか
- [ ] Kaggle利用規約に従ったデータ利用か
- [ ] ECGデータを外部共有する場合は法務承認を取得したか
- [ ] S3バケットのアクセスログが有効になっているか
- [ ] 不要なデータの定期削除ポリシーが設定されているか
- [ ] IAMロールはS3読み取り専用に制限されているか（最小権限の原則）
